### Connecting LLMs to the Real World: Tool Use, Function Calling, and MCP `AI/ML`
- LLMs are text-prediction engines with no built-in ability to call APIs or take real-world actions; when ChatGPT "searches the web," it generates a structured request and OpenAI's application layer does the actual search
- Tool use pattern: model receives a menu of available functions with JSON schema descriptions → when it needs real data, generates a structured JSON request (e.g. `{"function": "get_weather", "arguments": {"location": "Tokyo"}}`) → app layer executes → result returned to model → final answer composed
- The model never executes functions directly — it reasons about what needs to happen, the surrounding software makes it happen
- Progression of the paradigm: basic tool use → function calling (typed parameters validated against schemas, chainable) → Model Context Protocol (open standard now adopted by every major AI company)
- MCP solves the N-to-M problem: one protocol connecting any number of agents to any number of backend systems, instead of every agent-system pair needing a custom integration
- Why this took iterations: early approaches were inconsistent in how they described tools, validated arguments, and handled errors — MCP standardizes all of this so agents and backends can interoperate without per-pair custom code

### How Instacart Built Search for Billions of Products `Engineering`
- Two fundamentally different user search behaviors exist side-by-side: exact matchers ("pesto pasta sauce 8oz") and intent-based searchers ("healthy foods") — solved originally with two parallel retrieval systems (keyword + semantic) running simultaneously
- Maintaining dual systems compounds: syncing results, blending ranked lists, and keeping both fast at millions of daily queries became a heavier tax each quarter
- Instacart's write side is what makes their problem unusual: billions of writes per day (price changes, inventory, availability, personalization signals) — most search systems index once and refresh occasionally; Instacart's data changes constantly with every change needing to appear in results within seconds
- Precision (% retrieved results that are actually relevant) vs recall (% of relevant documents the system retrieves) — tuning this tradeoff is the core engineering game of search, and architecture determines how much control you have
- Left Elasticsearch behind despite it being the industry standard for full-text search — it couldn't handle the combination of write-heavy updates + dual-retrieval requirements at Instacart's scale
- The catalog spans billions of items across thousands of retailers — not a single clean database, but a constantly-shifting, multi-source inventory problem

### EP213: MCP vs Skills, Clearly Explained `AI/ML`
- MCP and Skills both extend what an agent can do but solve different problems — picking the wrong one adds unnecessary cost or complexity
- Five comparison dimensions: (1) Integration: MCP connects N agents to M backends via one protocol; Skills are folders with a SKILL.md the agent loads on trigger (2) Architecture: MCP runs as a separate process with its own JSON-RPC runtime; a Skill is just a directory with scripts and assets (3) Invocation: MCP tools have typed parameters validated against a schema and can be chained; Skills are invoked by the agent reading SKILL.md and running bash/python/curl commands (4) Runtime: MCP runs in its own container; Skills run in the agent's environment with no extra infra (5) Use case: MCP for connecting agents to live systems and data; Skills for reusable know-how and instructions
- Five-layer prompt injection defense stack (no single fix is sufficient): (1) Spotlighting — wrap untrusted text in control tags like `<UNTRUSTED>...</UNTRUSTED>` and instruct model to treat it as data, not instructions (2) Instruction Hierarchy — fine-tune model to rank system prompt > user message > third-party content (3) Least-Privilege Tools — give agents minimum tools needed (4) Human-in-the-Loop — require explicit user approval before sensitive actions (5) Planner/Executor Split — two separate LLMs: planner has tool access but never sees untrusted content; executor reads untrusted content but has no tools
- Prompt injection is #1 on OWASP LLM Top 10; Gmail stacks multiple of these defenses together in production
- X algorithm pipeline: Feed Request → Home Mixer pulls engagement history (Query Hydration) → candidates from Thunder (followed accounts) + Phoenix Retrieval (ML-discovered accounts) → Hydration (enriches with metadata) → Filtering (removes duplicates, old posts, blocked/muted content) → Grok-based transformer predicts engagement → Weighted Scorer produces final feed

### Life Is a Game: Treating Challenges as Level-Up Triggers `Mindset`
- Reframe: instead of "why is this happening to me?" ask "what is this here to teach me? What's my next move? Where am I and what do I need to do to level up?" — changes how the brain processes difficulty
- Neuroscience: facing a challenge with a different response activates new neural pathways; reacting the same way reinforces the same existing pathway — you literally stay on the same level
- Mario analogy: you cannot get to the next level without facing Bowser first; staying comfortable prevents leveling up
- Every difficult conversation, rejection, trigger, or moment of wanting to quit is a Bowser moment — an invitation to activate something new in the brain
- Hindsight is acceptable — you don't need to understand the lesson immediately; asking the question changes how you move through the difficulty regardless

### The Hidden Danger of Chasing Someone Else's Definition of Success `Mindset`
- People who achieve someone else's definition of success arrive and feel nothing, or feel something is wrong with them — there's nothing wrong; they just hit the wrong target
- Em's personal definition: love (having love and joy in life) + growth (expanding, healing, becoming better) + impact (making a real difference) — not follower count, revenue figure, or title
- External metrics can be going well while internal metrics are empty — the two are independent; achievement without meaning is a sign of misaligned success definition
- "If you don't define success for yourself, the world will define it for you. And the world's definition will always keep you feeling behind. Always one milestone away from enough."
- Exercise: write down what makes you genuinely feel successful (not what looks good, not what would impress people) and use it as a compass to filter noise

### The Success Mindset Trilogy: Three Neurological Beliefs Required `Mindset`
- Three beliefs science shows are necessary for goal achievement: (1) Belief in capability — bigger predictor of success than intelligence or talent; builds resilience; without it you won't set goals big enough to change your life (2) Belief in worthiness — you can believe you're capable but if you don't believe you deserve it, the brain subconsciously sabotages you; if you do get it, guilt removes the joy (3) Belief in possibility — if you don't believe it's possible, there is no dopamine, no motivation, and no action; the brain will not help you go after something it doesn't believe you can have
- Most people have gaps in at least one of the three — that gap is where self-sabotage, procrastination, and "I don't know why I can't make this happen" live
- Shifting from "if this happens" to "when this happens" changes how the brain approaches a goal neurologically; the word carries commitment
- Diagnostic: when you think about the thing you want most, which of the three beliefs feels shakiest? That's where the work is

### Brain Sync: Why Your Social Environment Is a Neural Anchor `Mindset`
- The brain syncs up with the people you communicate with most — their brain activity, energy, and thought patterns literally start to become yours; the deeper the communication, the deeper the sync
- Keeping consistently negative, draining, or fear-operating people around isn't just tolerating their energy — it's letting them rewire you
- Every person you spend time with is part of the anchor your environment has on your brain; holding onto characters from an old level anchors you to that level
- "Swift with the scissors" is not cold or cruel — you can love people from afar, wish them well, create distance without a blowup, quietly step back without drama
- Post-interaction check: how do you feel mentally, emotionally, energetically — not just in the moment, but on average over time? Your nervous system doesn't lie

## Product School

### Superhuman's Repeatable PMF Engine: The Sean Ellis 40% Benchmark `Product`
- Sean Ellis benchmark (from Dropbox, Eventbrite growth work): ask "How would you feel if you could no longer use this product?" — options are "not disappointed," "somewhat disappointed," "very disappointed"; after benchmarking hundreds of startups, companies above 40% "very disappointed" almost always grew easily; below 40% almost always struggled
- Superhuman's 2017 score was 22%; rather than immediately rebuilding features, they segmented results by persona (founders, executives, engineers, salespeople) and removed low-fit segments from the calculation — score jumped from 22% to 32% without a single product change
- "Change the market before you change the product" — adjusting the target market definition is faster and often more accurate than building your way to PMF; most teams default to the latter
- Ignore the "not disappointed" cohort completely: "As painful as it is, we have to ignore the not disappointed crowd because they are so far from loving the product that they are essentially a lost cause" — their feature requests pull the roadmap in directions that help no one
- The trap: "not disappointed" users still submit feedback, request features, and behave like engaged users — they look active but are unconvertible and will mislead your roadmap
- For "somewhat disappointed" users, only act on feedback from those whose stated main benefit matches what your best users love — otherwise their requests optimize for the wrong thing

### GoFundMe CPTO on AI Strategy, Marketplace Health, and the CPTO Model `Product`
- Arnie Katz's sequencing decision: when LLMs arrived, didn't ask "how do we make engineers more productive?" — asked "what is now possible for customers that was never possible before?" — all initial AI investment went to customer-facing features (title generation, story enhancement, full agent-led creation flow) before any internal tooling
- Core mental model: someone in a hospital parking lot in the dark trying to write a fundraiser title for their child's medical expenses — AI removes the highest-friction, highest-emotional-cost moment; even Arnie himself felt friction when launching a fundraiser for a cause he cared deeply about after 2.5 years at the company
- Rule: map AI investments to the emotional and cognitive low points in your user journey AND the highest-frequency interactions — that's where friction costs the most and relief creates the most loyalty
- Three marketplace failure modes: (1) Cold start — supply or demand doesn't materialize (2) Imbalance — one side overwhelms the other (3) False positive growth — one supplier drives all top-line metrics while the platform stagnates, eventually enabling that supplier to transact directly with consumers, bypassing the marketplace
- Warning on false positive growth: growth metrics can conceal structural fragility; healthy platform growth is distributed across many suppliers and many demand sources; concentration in either direction is a leading indicator of future brittleness
- CPTO model advantage: "That decision can now come to my leadership table and we can make it together and pivot those resources within days" — when product and engineering leadership are unified, response time to experimental findings drops from weeks to days

### Security as a First-Class Product Feature: Why It Pays More Than Any Other Bet `Engineering`
- Built Row Level Security across 6 database tables for ExecReps (execreps.ai) when it had only ~2 dozen active users — "overkill for two dozen users" but the right call for an asymmetric risk
- "Security debt compounds faster than any other form of technical debt" — Kahneman/Tversky loss aversion: losses are felt ~2x as intensely as equivalent gains; you can refactor a messy UI or optimize a slow query; you cannot un-leak data; a breach isn't a setback, it's a loss your users feel viscerally
- RLS at the database layer (Supabase) means even if someone bypasses the API or there's a bug in application code, the database won't hand over data that doesn't belong to you — the enforcement isn't application logic, it's the storage layer itself
- Public security page closed a Head of IT's trust evaluation in 30 seconds flat: "This is more than I expected" — Don Norman's Gulf of Evaluation: buyer needed to answer "can I trust this vendor with our data?" — most startups force questionnaires and follow-up calls; a single URL closed it immediately
- Recursion bug from RLS on team functionality (managers needing team data, admins needing org-wide visibility): naive policies caused infinite recursion; fix was a secondary flat lookup table with no joins that could trigger policy re-evaluation
- Day-and-a-half of early investment has paid for itself in enterprise sales conversations a hundred times over
