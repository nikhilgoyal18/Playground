### EP216: RAGs vs Agents `AI/ML`
- **RAG is a fixed 4-step pipeline**: embed query → retrieve relevant chunks from knowledge base (PDFs, wikis, etc.) → inject chunks as prompt context → LLM generates grounded answer. One retrieval, one generation — cheap, predictable, easy to debug.
- **Agents are a reasoning loop with tools**: query enters a runtime loop → LLM picks a tool (Read, Write, Edit, Bash, etc.) → runtime executes it → result fed back to LLM → LLM reasons again and picks next tool → loops until task complete. More flexible but more tokens and harder to debug because errors compound across steps.
- **Decision rule**: use RAG when the answer lives in your documents; use an agent when the answer requires taking actions on other systems. The key differentiator is *action* vs *retrieval*.
- **Forward proxy vs reverse proxy vs API gateway**: forward proxy sits client-side (hides client IP, corporate filtering, caching); reverse proxy sits server-side (load balancing, TLS termination, hides backend topology — NGINX, HAProxy); API gateway is a reverse proxy that additionally enforces auth, rate limiting, API key management, versioning, and request shaping across all microservices.
- **API gateway eliminates per-service boilerplate**: without a gateway, every microservice independently implements auth, throttling, and request logging — the gateway centralizes this so services focus on business logic only.
- **Claude Code request lifecycle (6 steps)**: prompt → agent loop wraps with repo/file context → agent plans and proposes action (e.g., `Edit(auth.ts, lines 42–58)`) → permission system validates → approved action dispatched as tool call → tool executes in shell/cloud/sandbox as real syscall → result returned to agent loop for next reasoning step.
- **Claude Code context management**: long sessions don't run out of context via intelligent compaction — older conversation turns are summarized and compressed so the agent can continue working on large codebases without hitting token limits.
