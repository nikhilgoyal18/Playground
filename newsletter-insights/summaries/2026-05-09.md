### EP214: Claude Code vs. OpenClaw: 5 Design Dimensions `AI/ML`
- **System scope divergence:** Claude Code is a short-lived process (launch → run → exit); OpenClaw is a long-running background daemon with a persistent Gateway holding open WebSocket connections to Discord, Slack, and WhatsApp
- **Agent runtime architecture:** Claude Code uses a single async query loop (think → tool call → observe → repeat); OpenClaw uses per-session queues where a Gateway routes RPCs into separate queues per session
- **Extension models differ fundamentally:** Claude Code supports MCP, plug, skill, and hook all wired directly into the agent; OpenClaw uses a manifest-first plugin system where plugins flow through a central registry before reaching the agent
- **Memory strategy:** Claude Code treats CLAUDE.md as the memory primitive; OpenClaw separates MEMORY.md from daily notes and adds hybrid vector/keyword search across structured sections
- **Multi-agent routing:** Claude Code uses lead-to-subagent delegation; OpenClaw uses route-and-delegate where inbound channels are routed to dedicated agents that hand off to shared subagents
- **Deepfake pipeline (5 steps):** Prompt refinement → Reference image VAE encoding → Diffusion denoiser conditioned on prompt + latent + audio → Post-processing (upscale, color correct, NSFW classifier, watermark) → Multimodal lip-sync via phoneme alignment
- **AI eval recipe:** Step 1: pick one task dimension (safety, math, retrieval); Step 2: gather inputs paired with correct answers; Step 3: use code-based graders for objective tasks (unit tests, if/else), LLM-as-judge for subjective tasks — most teams skip or do evals wrong

### Team OS in Claude Code: Shared Context Architecture `Product`
- OpenAI's harness engineering post framed the core insight: "That Slack discussion that aligned the team on an architectural pattern? If it isn't discoverable to the agent, it's illegible in the same way it would be unknown to a new hire joining three months later"
- Hannah Stulberg (PM at DoorDash) built a shared repo where every team function checks in their context; a new engineer queried a 3-month-old customer decision and got full reasoning in 15 seconds — without pinging anyone
- **Quantified knowledge loss:** New hires take 6–7 months to feel settled; only 12% of employees say their company does onboarding well; 47% of companies cite institutional knowledge loss as their top offboarding challenge
- **Productivity cost of context queries:** Each context question = lookup + Slack ping + wait + context-switch back; at 10 queries/day × 10 minutes each = 8+ hours/week lost per person
- **Four convergent implementations studied:** Hannah Stulberg at DoorDash, Dave Killeen at Pendo, Gabor Meyer at Google, Carl Vellotti building solo — all four independently arrived at the same 3-layer architecture
- **Architecture is tool-agnostic:** Built on Markdown files, works with Codex, Cursor, GitHub Copilot, not just Claude Code; portability is a feature
- **Strategic PM reframe:** Most PM advice says "make yourself indispensable"; the Team OS bet is the opposite — make yourself unnecessary for context questions to free up time for judgment-requiring work; DoorDash team valued Hannah more for it
